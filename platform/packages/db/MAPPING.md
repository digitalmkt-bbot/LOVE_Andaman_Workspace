# MAPPING — booking blob → relational schema

Task **BK-01**. One row per field in `allotment_v2/docs/booking.model.ts`, the
authoritative description of the `sb_bookings` blob. Every field in that file
appears below exactly once, including the ones deliberately dropped — those are
in [§13](#13-dropped-fields) with a reason each.

Target tables are created by migrations `0001`–`0006` in `migrations/`, all in
the `operation_schemas` schema.

**Conventions used throughout.**

| In the blob                     | In the schema   | Why                                                                                                                                        |
| ------------------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `''` for "not set"              | `NULL`          | The blob cannot distinguish "no note" from "an empty note". A column can. BK-04 converts `''` → `NULL` on every nullable text column.      |
| a missing / `null` child object | a missing row   | One-to-one children key on `booking_id`, so "never happened" is the absence of a row, not a row of nulls.                                  |
| `[]`                            | zero rows       | Never a placeholder row.                                                                                                                   |
| `ISODate` string                | `date`          | Calendar dates in Asia/Bangkok. Never a timestamp, never round-tripped through UTC.                                                        |
| `ISODateTime` string            | `timestamptz`   | Absolute instants. BK-04 must attach `+07:00` to any legacy value that has no offset, rather than letting Postgres assume the server zone. |
| `MoneyTHB` number               | `numeric(12,2)` | Whole-baht integers today; the two decimals are for VAT-inclusive agent rates that already produce satang downstream.                      |
| camelCase                       | snake_case      | Postgres folds unquoted identifiers to lower case; camelCase would have to be quoted forever.                                              |

## 7. `BookingPaxCounts` → `booking_trip_pax`

The 12-key pax object becomes `(booking_trip_id, pax_kind, nationality_class, qty)`,
primary-keyed on the first three. **Sparse by design**: an absent row is zero.

| Blob key                             | → `(pax_kind, nationality_class)`            |
| ------------------------------------ | -------------------------------------------- |
| `ad_fr`                              | `('AD','FR')`                                |
| `ad_th`                              | `('AD','TH')`                                |
| `chd_fr`                             | `('CHD','FR')`                               |
| `chd_th`                             | `('CHD','TH')`                               |
| `inf_fr`                             | `('INF','FR')`                               |
| `inf_th`                             | `('INF','TH')`                               |
| `foc`                                | `('FOC','FR')`                               |
| `foc_fr` _(live column, undeclared)_ | `('FOC','FR')` — summed with `foc`           |
| `foc_th` _(live column, undeclared)_ | `('FOC','TH')`                               |
| `ad` _(legacy v1, undeclared)_       | `('AD','FR')` — **the dual shape dies here** |
| `chd` / `inf` _(legacy v1)_          | `('CHD','FR')` / `('INF','FR')`              |

**Ambiguity resolved:** an unsuffixed legacy count folds into `FR`, the v1
default (v1 predates Thai-rate pricing entirely). `foc` and `foc_fr` can both be
present on the same live row; BK-04 sums them into one `('FOC','FR')` row and
reports any booking where both were non-zero, since that is a mapper artefact
worth a human look.

`nationality_class` is a **pricing class, not a passport**: a foreign resident of
Thailand is sold at `TH`.

## 8. `BookingOps` → `booking_ops`

**The structural fix.** The monolith stores day 1's assignment on `bk.ops` and
day 2+ on `trip.ops`, so every consumer has to know `i === 0 ? bk.ops :
trip.ops`. Here every service day is one row keyed `(booking_id, service_date)`.
There is no day-1 special case left to forget. BK-04 unions both sources.

| Blob field                | → column                                                  | Type                             | Notes                                                                                                                                               |
| ------------------------- | --------------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| _(derived from the trip)_ | `service_date`                                            | `date not null`                  | Keyed on the date, not the trip, so a reschedule does not orphan the assignment, and a day with two trips (an overnight's two legs) shares one van. |

Two van invariants are **deliberately not constraints**: "disband nulls both van
columns" and "`return_same_van` excludes a distinct `van_return_id`". Both hold
for correctly-written rows but not across live history (a `pickup_self` guest can
have a return van and no outbound one), so enforcing them would fail the BK-04
backfill on real bookings. They belong in the write path.

## 10. Money

### 10.1 `BookingAddOn` → `booking_addon`

`type` → `type` (open-ended: add-on types are data-driven from `RT_ADDON_DEFS`
and staff create them in the UI, so no CHECK), `label` → `label` (frozen at sale
time), `amount` → `amount`, `qty` → `qty` (CHECK `>= 0`), `note` → `note`, array
position → `seq`.

### 10.2 `BookingAdjustment` → `booking_adjustment`

`kind` → `kind`, `mode` → `mode` (CHECK `in ('amount','percent')`), `value` →
`value` (**signed** — a discount is negative in either mode, so nothing needs to
know a kind's direction to total a booking; CHECK bounds `percent` to ±100),
`label` → `label`, `note` → `note`, array position → `seq`.

### 10.3 `feeItems[]` → `booking_fee_item`

Declared `unknown[]` in the model; shape taken from the live
`sb_bookings__feeitems`: `type` → `type`, `label` → `label`, `amount` →
`amount`, `at` → `raised_at` (`timestamptz`), array position → `seq`. Kept
separate from adjustments because adjustments are priced at sale time and fee
items are raised afterwards, each with its own timestamp for the invoice.

### 10.4 `upgrades[]` → `booking_upgrade` (**new table**)

Declared `unknown[]`; shape from the live `sb_bookings__upgrades`. Day-of upsells
sold at the pier. `id` → `upgrade_code`, `label`, `sellprice` → `sell_price`,
`tocompany` → `to_company`, `commission`, `collected`, `note`, `seller` (intended
FK → staff), `settle`, `at` → `sold_at`, `method`, `feepct` → `fee_pct`, `fee`,
`customerpaid` → `customer_paid`, `slips` → `slips` (`jsonb`), array position →
`seq`. Cannot collapse into `booking_addon`: the money splits three ways
(company / commission / what the customer handed over) and `booking_addon` has
one amount.

### 10.5 `priceBreakdown` → `booking_price_breakdown`

One row per booking, `booking_id` as the **primary key** — so "no breakdown" is a
missing row and two are impossible.

| Blob field    | → column       | Constraint                        |
| ------------- | -------------- | --------------------------------- |
| `seat`        | `seat`         | CHECK `>= 0`                      |
| `addOn`       | `addon`        | CHECK `>= 0`                      |
| `focDiscount` | `foc_discount` | CHECK `<= 0` — **stays negative** |
| `discount`    | `discount`     | CHECK `<= 0` — **stays negative** |
| `extra`       | `extra`        |                                   |
| `total`       | `total`        | no CHECK; see below               |

Discounts stay negative so `seat + addon + foc_discount + discount + extra` is
the total by plain addition, everywhere, with no component needing to know its
own sign convention.

`total` is **not** constrained to equal the sum: a `price_mode = 'manual'`
booking takes it from `manual_total`, and whole-baht rounding at the point of
sale can leave slack. That invariant belongs in a reconciliation report, not in a
constraint that would reject legitimate historical rows.

## 13. Dropped fields

Everything below is in `booking.model.ts` (or is a live column) and has **no**
target column, on purpose.

| Field                                                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `total`                                                                                                                 | Duplicate of `priceBreakdown.total`. Two totals is how a booking ends up worth two different amounts depending on which screen you open. `booking_price_breakdown.total` is the single total; `price_mode` + `manual_total` explain how it was derived. **BK-04 must assert `bk.total === bk.priceBreakdown.total` and report every mismatch** rather than silently picking one. |
| `trip.lockDrawSel{}`                                                                                                    | Form-transient. It is the lock quantities _selected in the open dialog_; `lockDraws[]` is what was actually committed. Persisting UI state was the mechanism behind several lock counter-drift bugs.                                                                                                                                                                             |
| `trip.lockDraws[]`                                                                                                      | **Not dropped — moved.** Becomes `booking_trip_lock_draw` in **BK-02**, where it is the single source of truth and `used` becomes a derived view. Deliberately not modelled here, so there is exactly one owner of the lock schema.                                                                                                                                              |
| `BookingOps[key: string]` tail                                                                                          | The live occupants (`boatSplits`, `vanCheckin`, `pierCheckin`, `pierNote`) are promoted to real columns. Any _other_ key is unstructured accretion with no reader; BK-04 logs unrecognised keys instead of importing them into a catch-all column that would immediately become a second blob.                                                                                   |
| `BookingHistoryItem[key: string]` tail                                                                                  | Preserved wholesale in `booking_history.data` (`jsonb`) — not dropped, but not promoted either. History entries are heterogeneous and read-only once written.                                                                                                                                                                                                                    |
| `editLock` (`editlock_uid/by/at`)                                                                                       | Live columns, not in the model. A browser-tab advisory lock. Replaced by real optimistic concurrency on the API; carrying a stale lock into the new schema would let a dead tab block edits forever.                                                                                                                                                                             |
| `paymentSlips`, `pierPayments`, `paymentSnapshot.paid/paidStatus/deposit/balance`                                       | Live columns, not in the model. Accounting-owned (Phase 7). `payment_snapshot` is `jsonb`, so the four snapshot sub-fields ride along unchanged; the two arrays belong to the payments domain and are modelled there, not under booking.                                                                                                                                         |
| `focReason`, `cancelReason`                                                                                             | Live columns, not in the model. Superseded duplicates of `focApproval.reason` and `cancellation.reason`; BK-04 coalesces them into those and reports rows where the two disagreed.                                                                                                                                                                                               |
| Type aliases `ISODate`, `ISODateTime`, `MoneyTHB`, `PaxKind`, `BookingMode`, `PickupZone`, `PriceMode`, `BookingStatus` | Types, not fields. Realised as column types and CHECK constraints above, and as zod schemas in `@la/contracts/booking`.                                                                                                                                                                                                                                                          |
| `PickupZone`'s `'NT'` member                                                                                            | A second spelling of `'NoTransfer'`. Normalised at migration; the CHECK accepts only three values.                                                                                                                                                                                                                                                                               |
