## 2. How it works

- The screens' own list reads (`ops/24`, `ops/25`, `ops/10`) hand the `kpis` they already receive to `laOps.fleetKpis.put()` (no extra request on load).
- A write or a change event marks the strip stale. The next draw asks again with a filter that matches nothing (`GET /v1/fleet/jobs?boat_id=-none-`, `/incidents?boat_id=-none-`, `/stock-items?q=-none-`): the server counts every row whatever the filter, so only the strip comes back. If it changed, the screen is drawn again (not while a user is mid-edit, `O.busy()`).
- Until the first answer and offline `flKpi()` returns null and legacy's own count is drawn.
- Legacy edits in `05-fleet.js` are marked `[ops F4]`: in `flRenderMaint`, `flRenderIncident`, `flRenderInventory` the counting `const`s became `let` and are overwritten from the server's strip in one `if(K){...}` block; the Awaiting list and tab sizes use `K`. Outside ops mode `flKpi` is absent, so legacy is unchanged.

## 3. Decisions taken (reversible)

1. **Strip refresh by an empty-filter read** instead of a new endpoint or refetching whole lists after each write. Cheap, no backend change.
2. **Stale strip is shown until the new one arrives** (same pattern as ops/68), not legacy's local count, to avoid flicker between two different numbers.
3. **Memo tab counts and per-row stock "low" flags stay local.** The strip's "low stock" is the server's `low_stock` (items), rows keep the per-item `belowMin` the server already gave.
4. **`moLiveTotals` while typing** keeps legacy's formula on the typed lines (a draft has no server answer; calling the server on each keystroke needs a preview endpoint that does not exist). The saved result is always the server's (`PATCH` sends `lines` only).
5. **`part_no_required` flow:** legacy's own early check in `memoAddItem` (from the loaded stock) is kept; the server's refusal at save is the second line of defence and now shows the server's message instead of a generic toast.
6. **Contract badge** counts from the served flags after any agent write (always fresh); the list's `expiring_count` is used until then.

## 4. For the developer to review

- The server's memo totals count a line with qty 0 as 1 (the form rule `memoCalcTotal`); legacy's `moLiveTotals` counted it 0. For an unedited server memo the detail now shows the server's total, so a 0-qty labour line is priced at its price there. `flSaveMemo`/`toMemoBody` already sent `qty || 1`.
- The server's `part_no_required` message ends "กรุณาเลือกรายการจากคลัง (item_id) เพื่อระบุเบอร์ให้ถูก" and has no "คงเหลือ" per candidate (legacy's local alert had it). Shown as it is, as asked.
- `damage_total` is always 0 on the server (legacy read a field nobody sets), so "฿0 total damage" never moves.
- Duplicate groups cannot be created through the API, only by imported data: the test feeds the report through a stub for that one endpoint and proves the screen takes the server's kinds and counts; the empty real answer is also checked against a locally duplicated memo.
