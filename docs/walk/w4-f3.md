## 3. Assumptions and decisions (reverse any)

1. **Duplicate confirm before the save stays legacy's.** The server answers duplicates for a stored booking only. The browser's confirm runs over the bookings it holds (the loaded months), as before, and the server's `possible_duplicate` warning is shown after the save with the server's text and reasons. A booking the browser did not hold can therefore be saved without the question and still get the server's warning at once.
2. **Search and the Pending-FOC pill ask the server and show the server's set** (a superset of legacy's blob: any trip's route name, rate-type code). Until the answer is in (250 ms debounce) legacy's own filter shows. A write marks the sets stale; the old set stays until the new one is in.
3. **The row's computed fields come from the list read only.** A booking just saved (PATCH / POST answer) has no `srvList`, so that row falls back to legacy's own arithmetic until the month is read again. `is_new` / `is_soon` / `is_today` are as of the read (the screen does not redraw at midnight).
4. **Lock warning shown only when the staff has drawn nothing** (client state, as legacy); the request does not carry the staff's draws, so the server's `warning` always describes the undrawn case. Only the text and the "would draw" count are the server's.
5. **Overnight rows list live bookings only** (server decision 10 of the booking-list note); legacy also drew cancelled ones struck through.
6. **Return-van chip counts the van board's items for this page's routes** (marine or land), one item per booking; pending-approval bookings are off the board (server rule), legacy counted them.
7. **Fact Sheet owner-paid lines** ("เจ้าของเรือรับผิดชอบ") print the template's own line labels (`rent.owner_pays[].label`), not `CT_RENT_EX`'s fixed words. With the default template they are the same words.
8. **One baht apart in rare cases.** The server rounds every amount to the satang, the screen then rounds to the baht; legacy rounded once. In the walk the base-case figure shows 321,928 against legacy's 321,927 (a half satang). The test accepts 1 baht apart on numbers and requires all words and markup to be equal.
9. **The calc request carries `route_key` and `itinerary`** (the sheet prints the route name and the kilometre total), so editing an itinerary row asks the server again (debounced).
10. **`ctFactSheet` is wrapped, not edited.** No change in `08-app.js`; the markup is copied from it. If legacy's sheet changes, `75-ops-costing-sheet.js` must follow (the test compares both drawings, so a drift shows).

## 4. MISSING-SERVER-FIELD

1. **Duplicate and passenger-type check before the save** (`POST /v1/bookings/check`, or `dry_run: true` on the create / amend): the same `warnings[]`, nothing stored. With it the confirm before saving can be the server's.
2. **By-trip mixed-van groups** (`warnings.mixed_van: [{group_id, route_id, vans: {van_id: pax}}]`) for the "รถปนกันในกรุ๊ป" chip.
3. **By-trip per-boat figures** (`routes[].boats: [{boat_id, pax, capacity, over, ovn_hold}]`) for the boats-running card and the route chips.
4. **Effective part values of a line under a plan's override** (`sheet.line_parts[].parts[].unit` after the override) for the override editor's placeholders (`ctEffLine`).
5. Optional: `pending_foc` as a flag on each list row, so the pill needs no second read.
