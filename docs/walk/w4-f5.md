## What the list takes from the server

`renderVanJobs` keeps legacy's markup (Thai texts, colours, filters, rail, drawer). In ops mode it asks `window.opsVanJobsList(date)` and the server's day read replaces what the walk over `SB_BOOKINGS` counted:

| On screen | Server field |
|---|---|
| a row (van, programme, round, group) | `jobs[]`: `van_id`, `route_id`, `group_number`, `round {no, of, time}`, `zones`, `pickups`, `bookings` |
| "pax / seats", "เกินจุ" | `jobs[].pax` (customers plus guides riding along) against `van.capacity` |
| row order | the server's order (first departure, programme, zone, group, return-only last); the client sort is skipped |
| "ค้าง N" badge, "ค้างจัดการ N" | `jobs[].struck`, `struck` |
| red hero, "◆ ต้องจัดรถ", programme line | `unassigned {pax, by_route}` |
| amber hero, "↩ ต้องจัดรถกลับ", names | `return_unarranged` |
| purple "เช็ค self-arrive" | `self_arrive` |
| "↩ ขากลับ N" badge | the sheet's `ret.rows[].extra` when the sheet is in hand, else none (MISSING-SERVER-FIELD 7) |

The first draw (no day read yet) and offline use legacy's walk, as before; the day read then redraws.

## Decisions taken (design mindset)

Questions 1 to 6 of `vanjobs-sheet.md`:

1. **Rewrite the list band: yes**, through the hook above (no copy of 290 lines of markup). The server's `pax` includes guides riding along, so a row can show one more than legacy did, and "เกินจุ" follows the server's `over_capacity` rule.
2. **First draw / offline: legacy's sheet** until the server's answer lands (the "Loading the job order..." text is gone unless legacy's function is missing). A `404` still says the server has no such job.
3. **"รถปนกันในกรุ๊ป" banner stays gone**: one group has one van on the server.
4. **Unassigned banner counts bookings, not parts**: kept, the server's number.
5. **Print window waits for a stale sheet (30 s)**: kept. Chrome allows it; Safari may block a window opened after a wait.
6. **Tags that differ slightly** (brackets of "เช้าไม่ได้ขึ้นรถ", "กลับคันเดิม" for a return with no outbound van): accepted until the server sends the fields (list below).

Leftovers of `w3-days.md`:

- **3 (`pjBoatSt` ovn): dropped the exception.** The server's state wins for every state.
- **4 (`bkOvnHoldMap` and friends): switched to the server.** One wrapper on `bkOvnHoldMap` (the other two sit on it) reads `ovn_hold` from the availability rows `ops/71` keeps per date. Legacy's walk answers until the date's answer is here; a redraw happens only when the server's map differs from what legacy gave. Seat counts of `getAllotment` were already the server's (`ops/50`).
- **1 (split rows after a passenger edit): keep the server's rebalancing.** The browser heal stays off (`ops/34`). Staff see the server's parts (4 ad + 2 chd to 4 ad + 1 chd gives [4,0] + [0,1], not legacy's [2,1] + [2,0]). To reverse it, change the backend, not the screen.
- `ckHasArrange`: the server's yes is final; its no is not (a van assigned in the browser after the read counts). Reversible in one line.

## MISSING-SERVER-FIELD (backend, not edited)

1. `alt_pickups` on an outbound row of the sheet (the purple lines under the pick-up place): read from the local booking now.
2. `loss.self_pier_reason` (the reason in brackets of "เช้าไม่ได้ขึ้นรถ"): read from the local check-in now.
3. "Heads still travelling" on a return row (`ckPaxLeft`): the screen tests `no_show + cxl >= pax`; differs from legacy when the lost heads were typed by category.
4. The outbound van of a return row, or a `same_van` flag: `from_van_id` null means two things.
5. Passenger count for the "+N more" of the other names when the list holds only the lead.
6. `code`: `voucher` falls back to the booking id, legacy's to `voucherRef || code || id`.
7. Per-leg counts on a job: `out_bookings`, `ret_bookings`, and for the list's "↩ ขากลับ N" badge `ret_extra_bookings` / `ret_extra_pax` (people who go back on this van but went out on another). The job's `bookings` counts both legs once. Until then the badge needs the sheet (read on demand), so it is missing until a sheet was opened.
8. The overnight hold for many dates without the pier-board payload (`ops/71` reads availability and boat-operation together for a date range).
