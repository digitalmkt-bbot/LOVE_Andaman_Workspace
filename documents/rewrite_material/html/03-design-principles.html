Rebuild spec 03

Design Principles

The design system of a production ops tool, captured precisely enough to rebuild. Tokens, components, layout, print and the render traps that constrain how any of it may be built — for a React + Vite SPA consuming the REST API. Everything on this page is rendered from the tokens it specifies, so the page is its own proof.

Source docs/design/00–06 Also CLAUDE.md §7–§8 Also workflows/08-shell Code allotment_v2.html Branch refactor/booking-v2-migration Date 2026-08-22
What this governs

Tokens · type · color · space · shape · elevation · motion · skins · components and their states · layout · icons · print · number and date display · accessibility · migration · governance.

What it does not

Business logic, data shapes, API contracts, permissions, pricing. Those live in docs 01–02 and the workflow docs. Those specs are framework-neutral; nothing here changes that.

Target

React + Vite + TypeScript. Tokens ship as CSS custom properties; components ship as typed React contracts. This is the one document that names a frontend framework, and only for the frontend.

The honest starting position The audit's headline finding: this is not one design system — it is a shared shell hosting ~15 independent visual languages (seventeen are identifiable). Ocean blue #1683C7 reaches far less of the app than its name suggests: it exists only as a token override on the --coral family, so every view that hardcoded an accent is untouched by it. In the entire pier-ops and print slice, Ocean blue appears in exactly one place — the Dev Log “+ Add” button. Underneath the divergence, eleven principles hold across every language, in print, and in every sub-brand. Those principles are the design system.

01 Design principles

Every rule below is traceable to how the product is used, not to taste. Staff run this all day — at a desk, and on a tablet on a pier in bright sun, under time pressure, entering numbers that become money.

PrincipleThe ruleWhy it exists
P1 Density over decoration 13px body / 1.55. 12px tables. 10px uppercase labels. 22px page gutter. 6–9px control padding. Whitespace groups; it never “breathes”. A manifest is 40+ rows and the dispatcher needs the whole trip on one screen. A scroll during a departure window is a mistake waiting to happen.
P2 Numbers get their own typeface DM Mono + tabular-nums for every money, count, date, time, hours, pax and serial. No exceptions on screen. Column alignment (a proportional column doesn’t line up digit-for-digit) · digit legibility (1/7, 0/O at 11px in sun) · tabular comparison (cap vs licence is read as a pair).
P3 Color is data Green good · amber caution · red bad · violet exception · gray inactive. Never recolor a status for aesthetics. It survives into print, where the code forces print-color-adjust:exact with comments saying the color is the data. If a red row prints gray the driver misses the no-show.
P4 Status = tint + dot + label Full-round, 10px/500, a 4px leading dot in the solid hue, ~10% tint background. Six colors. No solid-filled status chips. A tinted pill sits quietly in a dense table; thirty solid chips is a christmas tree. The dot restores the signal the tint gives up — and is a second channel, so hue is never alone.
P5 Elevation is nearly flat One workhorse shadow. One hairline border. State is a 3px colored left border, not elevation. Real depth only for modals, drawers, popovers. Depth is a scarce signal. If every card floats, nothing reads as “this is on top of the page and wants an answer”.
P6 Three radii, and they mean something 6 controls · 10 containers · 14 floating. Three. Full-round is a shape, not a step. Radius is grammar for “what kind of thing is this”. When a card and a button share a radius the hierarchy collapses.
P7 Motion signals response, never delight 120ms tight chrome · 150ms controls · 300ms fill bars. No entrance animation. Banned in dense tables and anywhere it delays a keystroke. A check-in operator taps forty rows in ninety seconds. A 200ms row animation is 8 seconds of waiting, and makes the app feel like it is thinking when it should feel like it already knew.
P8 Figures are always legible Min 11px for any figure in a column. Right-align numerics. Never truncate a number — truncate the label. Sun on a pier + a tablet at half brightness + a number that becomes an invoice. A clipped ฿12,4… is the same problem as a wrong number.
P9 Per-view identity, centrally governed A route may set its accent. It may not set type, spacing, radii, shadows or status colors. A skin is four tokens deep. Staff navigate partly by color — “the pink one” means Fleet. Worth keeping. Fifteen independent implementations of the same table is not.
P10 Print is a first-class output A4 landscape default. Color that carries meaning is forced to print. Thai government-adjacent forms use Sarabun by purpose. Much of this system’s output leaves the building on paper — guide sheets, job orders, vouchers, manifests. An afterthought print layer fails at the moment it matters.
P11 Bilingual by construction Every surface survives Thai and English in the same line, cell and button. Thai needs more line-height and an explicit font. A boat name is English, its status is Thai, and they share a row. The monolith records what happens when this is ignored — Thai falls to the system font, “different weight, different height than the English on the same line.”

02 Foundations & tokens

2.1 Typography

Two families on screen. The monolith loads eight in one request — DM Sans, DM Mono, Inter, Manrope, IBM Plex Sans Thai, Noto Sans Thai, Quicksand, Sarabun — of which only two are used by the global layer. The rewrite loads three (DM Sans, DM Mono, Noto Sans Thai) and adds Sarabun only on the print documents that need it.

The hard rules 1. Every figure in DM Mono with tabular-nums — money, counts, dates, times, hours, pax, serials, percentages, IDs. 2. Labels are the only uppercase in the product, at 10px/600 with .05em tracking. 3. Never uppercase Thai — it has no case, and transforming a mixed string produces a mismatched pair. 4. Never set a font-size that is not a token.

2.2 Thai script — the real constraint

Three facts drive every rule here. Neither DM Sans nor DM Mono contains Thai glyphs, so Thai on a DM-Sans-only stack falls back per-glyph, mid-line. Thai glyph height exceeds Latin at the same px — up to two marks above the base and one below. Thai has no case and no word spaces, so uppercase does nothing, line-breaking differs, and character-count truncation cuts mid-cluster.

#Rule
T1Every font stack that can receive Thai names a Thai font. Both --font-sans and --font-mono carry "Noto Sans Thai" as the second family. Enforced by the token, never per component.
T2One Thai font in the product. Noto Sans Thai on screen; Sarabun in print, and only where the document is government-adjacent. Never two Thai fonts on one screen.
T3Line-height floor 1.55 for any block that can contain Thai — which is all body text. Headings use 1.3, never below. Print goes to 1.7.
T4Thai runs ~8% shorter but needs ~10% more vertical room. Size by the taller requirement and the longer string; test every label in both languages.
T5Never text-transform:uppercase on a string that may contain Thai. The Label component’s uppercase prop must be false for Thai keys.
T6Truncate with CSS text-overflow, never a JS slice() — it can cut between a base glyph and its tone mark and render a broken cluster.
T7Thai figures still use DM Mono via the Thai fallback. The one sanctioned exception is a fully-Thai document surface where a single font matters more than digit alignment — the monolith’s Trip P&L uses Sarabun throughout with tabular-nums instead, “so there is one font on the page.” Legitimate for print-like documents; not a licence to drop DM Mono on a data screen.

2.3 Color

Ocean blue #1683C7 is the accent, lifting to #49b2ee in dark — the light blue fails contrast on a #0b1317 ground and reads muddy for fills. Six semantic tones, and only six: every business status in the product maps onto one of them.

Proposal · collapse the two blues The monolith runs brand Ocean #1683C7 alongside legacy info-blue #185FA5 — audit defect #11, “close enough to read as a mistake, far enough to look wrong side by side.” The rewrite has one blue. Anywhere the monolith used #185FA5 for an informational chip, a link or an “invoice” pay-type, use --accent. There is no separate --info token.

2.6 Motion

The four tokens

--dur-fast 120ms — list rows, icon buttons, hover tints.
--dur 150ms — buttons, inputs, nav, tabs. The default.
--dur-slow 300ms — fill-bar width, drawer slide.
--ease cubic-bezier(.2,.6,.3,1). One curve.

Where motion is banned

Inside dense tables — no row-enter, no reorder, no stagger. On anything in the input path. On the number itself — counting-up KPI values are banned: a figure mid-animation is a figure that is wrong, and someone will read it. Under prefers-reduced-motion everything resolves to 1ms.

Animate opacity, transform, background-color, border-color, box-shadow and width (fill bars only). Never height or layout-affecting properties on a list.

2.7 The token block

The full set is in 03-design-principles.md §2.2.3 — 83 tokens, copy-pasteable. The structural part, which is what people get wrong:

/* light — the COMPLETE palette lives on bare :root. Nothing has its
   only definition inside a media query or an attribute selector. */
:root{ --bg:#f6f8fa; --panel:#ffffff; --ink:#0f2029; --accent:#1683C7; /* …all 83… */ }

/* system preference — guarded, so an explicit light choice still wins */
@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){ --bg:#0b1317; --panel:#111d24; /* …dark set… */ }
}

/* explicit choice — repeated verbatim, so the toggle wins in both directions */
:root[data-theme="dark"]{ --bg:#0b1317; --panel:#111d24; /* …identical dark set… */ }
Theme stateRoot attributeResolved by
Explicit lightdata-theme="light"bare :root
Explicit darkdata-theme="dark":root[data-theme="dark"]
System (default)— none —@media (prefers-color-scheme: dark), guarded

Why each piece. The guard :not([data-theme="light"]) is what lets “I chose light on a dark machine” work — without it the media block wins by source order. The duplicated dark block is what lets “I chose dark on a light machine” work. Keep the two dark blocks byte-identical; a divergence is a bug that only shows on one kind of machine. And body must paint an explicit background: var(--bg) — a transparent body borrows the host’s ground, which is how a theme-aware page ends up with light text on a light background.

type Theme = 'light' | 'dark' | null;   // null = follow the system — three states, not two
function applyTheme(t: Theme) {
  const root = document.documentElement;
  if (t) root.setAttribute('data-theme', t); else root.removeAttribute('data-theme');
  try { t ? localStorage.setItem('la_theme', t) : localStorage.removeItem('la_theme'); } catch {}
}

The theme button in this page’s sidebar runs exactly that pattern — every specimen above re-renders correctly because each is built from custom properties, not from a literal hex.

03 The skin system

The most distinctive thing in this product, and the part most likely to be thrown away by someone who does not understand why it is there.

What a skin is

In the monolith: a named, additive, reversible <style id="…-skin"> block appended before </head>. It overrides by specificity rather than editing base CSS, so deleting the block reverts the look. Thirteen sit in the head stack; eleven more are injected at runtime into component hosts.

Why per-view palettes exist

Instant orientation — a dispatcher context-switches between Booking, Boat Operation, Van Jobs and Check-in dozens of times an hour, often mid-call; the accent answers “which screen am I on” before anything is read. Error prevention — assigning a boat and assigning a van look different, so a muscle-memory click in the wrong module is caught by the eye. Staff name modules by color: “the pink one”.

The React translation

A skin is four tokens. Nothing else. It may set --accent, --accent-ink, --accent-deep, --accent-soft and their dark counterparts. It may not set type, spacing, radii, shadows, motion, surfaces, ink, lines, or any status color. There is no per-skin table, no per-skin button, no per-skin pill.

export type Skin = {
  key: string;          // 'booking' | 'fleet' | 'pier' | …
  accent: string;       // fills, focus, active nav
  accentInk: string;    // accent-coloured text on a light ground
  accentDeep: string;   // pressed / active fill
  accentSoft: string;   // tint background, focus ring
  dark: Pick<Skin,'accent'|'accentInk'|'accentDeep'|'accentSoft'>;
};

export function SkinProvider({ skin, children }: { skin: Skin; children: React.ReactNode }) {
  const style = {
    '--accent':      skin.accent,
    '--accent-ink':  skin.accentInk,
    '--accent-deep': skin.accentDeep,
    '--accent-soft': skin.accentSoft,
  } as React.CSSProperties;
  return <div className="route-root" data-skin={skin.key} style={style}>{children}</div>;
}

How it cannot leak. Custom properties inherit down the subtree and stop at its boundary, so one route-root element is the whole scoping mechanism. Portals are the exception — modals, drawers, popovers and toasts render outside that subtree and lose the skin. Decide once and be consistent: chrome is global (modals, drawers and toasts keep the Ocean accent regardless of who opened them — recommended, it makes “you are in a dialog” a distinct state) and popovers inherit (a typeahead menu belongs to the field that opened it, so pass the four properties through to the portal container explicitly rather than relying on inheritance).

Target: 8 skins, not 17 core Ocean (absorbs global, legacy blue, ops navy) · booking #3A6FF7 · fleet #E03B7E · ops #0F6E56 · pier #16265C · finance #163d2b (absorbs PFM, Trip P&L, Daily Report, Costing) · sales #d44a7f (absorbs dashboard, B2B, market data) · manifest #65a30d. The Excel replica is print-only and correct as it is — it deliberately reproduces a spreadsheet staff still cross-check against. It is not a skin; it is a document template.

Geometry

th 7px 10px, 10px/600 uppercase, --muted. td 9px 10px, 12px, --ink-2. Row height ~33px. Figures right-aligned, DM Mono, tabular-nums. Dates left — they read as labels.

No zebra

Hairline dividers plus a hover tint. Zebra + a 3px status left border + a tinted row state is three background signals fighting, and the row states carry information.

Sticky header

Offset from a CSS variable, never a literal (§5). Uses box-shadow: inset 0 -1px 0 var(--line) rather than border-bottom — a bordered sticky header hairline-flickers during scroll in Blink.

Sorting & selection

Header is a <button> inside the <th>; aria-sort on the <th>. The caret always renders (in --line when inactive) so the column does not reflow on sort. Bulk-action bar sits above the table, never floating over it — floating covers the last row.

The rule that keeps the page from breaking A wide table scrolls inside its own container; the page body never scrolls horizontally. .tw{overflow-x:auto} with the min-width on the inner <table>. Sticky offsets — never hardcode 52

Why the rule exists --topbar is not a constant. The monolith’s topbar-float-skin sets :root{--topbar:0px} — it removes the docked bar entirely and floats its controls. And a stacked sticky bar’s offset depends on the measured height of the bar above it — the monolith notes that a fixed 96 both gapped and overlapped depending on real content. 
/** Measures a stacked sticky bar and publishes its offset as a CSS var on `scopeRef`. */
function useStickyOffset(
  scopeRef: React.RefObject<HTMLElement>,
  barRef:   React.RefObject<HTMLElement>,
  varName:  string,
) {
  useLayoutEffect(() => {
    const publish = () => {
      const top = parseInt(
        getComputedStyle(document.documentElement).getPropertyValue('--topbar')
      ) || 0;
      const h = barRef.current?.offsetHeight ?? 0;
      scopeRef.current?.style.setProperty(varName, `${top + h}px`);
    };
    publish();
    const ro = new ResizeObserver(publish);      // replaces the monolith's rAF-and-hope
    if (barRef.current) ro.observe(barRef.current);
    return () => ro.disconnect();
  }, [scopeRef, barRef, varName]);
}

Lint rule: no numeric literal in a top declaration on a position:sticky element. It is mechanically checkable, so check it.

The shared hero image system

What exists

Route hero photos at assets/hero/<routeId>.jpg, resolved as explicit route.heroImage → convention path → gradient fallback. Twelve files (r1–r12). The only consumer today is the Pickup Setup export card.

The history

The image was shared between the voucher and the pickup card. It came from marketing, so the marketing text is baked into the pixels — route name, tagline, sometimes a price. Fine on a marketing card; wrong on a voucher, where the text is already rendered live and now appears twice, in two typefaces, sometimes contradicting each other after a price change. The fix was an override layer: assets/voucher/<routeId>.jpg, a clean plate, composited on top for the voucher only.

Doc / code disagreement — the code wins CLAUDE.md §8 describes the voucher override layer as live. It is not. A repo-wide grep finds zero references to assets/voucher in any source file — the only mention is in CLAUDE.md itself. The directory exists on disk with exactly one orphan file, r12.jpg. And bkV2VoucherTicket() renders no photograph at all — it is a navy card with a route-colored left border and typographic content. The layer was built, one route was migrated, the voucher was later redesigned to drop imagery, and the mechanism was orphaned. The doc kept describing it.

How the rewrite handles it properly. The underlying mistake was one image serving two purposes. Fix it at the data model:

interface RouteImagery {
  marketing?: string;  // text baked in — marketing card, pickup export. NEVER a document.
  plate?: string;      // clean plate, no text — vouchers, documents, anything with live text over it
  thumb?: string;      // 16:9 crop for list rows and cards
  alt: { en: string; th: string };   // required — these reach printed customer documents
}
  1. A document never renders an image with baked-in text. If only marketing exists, the document renders the gradient fallback. A missing image beats a contradictory one.
  2. Images are route data, not convention paths. The API returns URLs. Convention lookup is how one route ended up with a file nobody references.
  3. The gradient fallback stays, and stays good — it uses the route color and is the correct rendering more often than people expect.
  4. Delete assets/voucher/r12.jpg during migration, or promote it to plate for route 12. Do not leave it.

Numbers

Right-aligned, DM Mono, tabular-nums, , thousands separators. A true minus − (U+2212), not a hyphen — and --danger only when negative is bad; a negative variance on a cost line is good news. Never abbreviate on a data screen (1.2k in a table is a rounding error waiting to be argued about). Abbreviation is allowed on a hero figure, with the full value in title.

Currency

Focus management

:focus-visible only — never :focus, so a mouse click leaves no ring. The ring is never removed. After an action that changes context, move focus deliberately: a deleted row → the next row; a failed submit → the first invalid field; a closed dialog → its trigger; a route change → the page <h1> (tabIndex={-1}).

Tab order in dense forms

Tab order follows visual order, so DOM order must follow visual order. Never tabIndex above 0 to patch a mismatch — fix the DOM. In a multi-column grid, order runs down each logical group then to the next, not left-to-right across unrelated fields, which is what a naive 3-column grid produces. Group with <fieldset>. Read-only fields stay in the order (staff copy from them); disabled fields leave it.

Screen readers

Landmarks: header topbar, nav sidebar, main, footer. One h1 per page; headings never skip a level. A toast root at aria-live="polite" (assertive for errors) and a status region announcing async result counts — debounced to 500ms, never per keystroke.

Touch

Minimum 40×40 targets via padding or a transparent expanded hit area — never by inflating the visual control. Row actions on touch are always visible or behind an explicit overflow menu. No hover-only affordances anywhere: if it only appears on hover, it does not exist on a tablet.

Contrast targets · WCAG AA floors, not goals Body text and figures ≥ 4.5:1 against their background. Large text (≥18.66px bold or ≥24px) ≥ 3:1. UI component boundaries and focus indicators ≥ 3:1. A pier tablet in sunlight is a low-contrast environment before the design starts. The token set hits these in both themes; --muted on --panel is the tightest pair in the light palette, which is why it cannot get lighter without re-checking everything downstream.
Color alone never carries meaning This is why a status pill is tint plus dot plus label — three channels, of which two survive a color-blind reader and one survives a photocopier. Same rule everywhere: a red row also has a label; a green tick also has text; a chart series gets a direct label, not only a legend swatch.

10 Render traps that are really design constraints

These read as bugs. They are constraints on how components may be built, and each has already cost this project real time.

10.1 · backdrop-filter traps dropdowns Symptom. A typeahead renders behind the cards next to it, no matter what z-index it gets. The monolith’s own word for it: ซ้อนกัน — “stacked/overlapping”.
Cause. backdrop-filter creates a new stacking context; an absolutely-positioned child is confined to it and cannot rise above later-painted siblings. filter, transform, will-change, contain, perspective, opacity<1 and position:fixed on an ancestor all do the same.
Rule. (1) The rewrite does not use backdrop-filter at all. (2) Every popover, dropdown, tooltip, menu and typeahead renders in a portal at the document root with collision-aware anchoring — which makes the ancestor’s stacking context irrelevant by construction. (3) Lint for backdrop-filter, filter, transform and contain on any card or field container.
10.2 · Scroll-jump on re-render Symptom. Typing in a filter, toggling a row or saving a field scrolls the list to the top and drops focus.
Cause in the monolith. Replacing a mount’s innerHTML destroys the focused element; the browser resets scrollTop and focus falls back to <body>.
Cause in React — the same failure, and easier to hit: key={index} on a filtered list changes every item’s identity when the filter changes · a component defined inside another component’s render body is a new type every render, so React unmounts its entire subtree (invisible in code review) · a conditional wrapper (cond ? <div><Form/></div> : <Form/>) remounts Form · a key on a container that changes with data deliberately remounts.
Rules. key is a stable domain id, never an index · never define a component inside a render body (lint it) · keep the element-tree shape constant, branching on props not on wrapper structure · never conditionally remount a subtree that owns focus · if a remount is genuinely needed, capture activeElement and scrollTop in useLayoutEffect and restore after commit · async results update rows in place, never replacing the whole list · virtualized lists key by domain id.
10.3 · Sticky offsets from CSS variables Symptom. Sticky headers gap or overlap by exactly 52px, or by a variable amount when a second bar is stacked. Cause. A hardcoded 52, or an assumed height for a bar whose height depends on content. Rule. Read --topbar; measure stacked bars with ResizeObserver and publish the offset as a custom property (§5).
10.4 · 100vh on iOS Symptom. The bottom of a full-height panel is cut off, and the amount changes as the URL bar hides. Cause. 100vh includes the hideable browser chrome. Rule. Use 100dvh behind @supports (height:100dvh), with 100vh as fallback.
10.5 · iOS input zoom Symptom. Tapping a field on a phone zooms the page in and never zooms back out. Cause. Any font-size below 16px on a focusable input. Rule. At ≤820px force input/select/textarea to 16px — this overrides the 12px control size and is correct; a zoomed page is a worse density problem than a larger field. Pair with html{-webkit-text-size-adjust:100%} to stop iOS font-boosting tables on rotate.
10.6 · min-width always beats max-width Symptom. A table with a large min-width overflows its container and pushes the page sideways; adding max-width:100% does nothing. Cause. In CSS, min-width wins the conflict — the table cannot shrink. Rule. The wrapper scrolls, not the table: .tw{overflow-x:auto} with the min-width on the inner <table>. Never put overflow on the table itself.
10.7 · Sticky header hairline flicker Symptom. A sticky header’s bottom border shimmers or vanishes during scroll in Blink. Cause. Sub-pixel positioning of a border-bottom on a sticky element. Rule. box-shadow: inset 0 -1px 0 var(--line) instead. The monolith already does this on its manifest table.
10.8 · Fonts not ready at print time Symptom. A printed document comes out in a fallback font, or blank, intermittently. Cause. window.print() fires before webfonts and images have loaded. Rule. Gate on await document.fonts.ready plus every image’s decode. Printing from the live document (§7) covers the common case, but a print route entered directly still needs the gate.
10.9 · Escaping is not automatic in string-built HTML Symptom in the monolith. A passenger name containing < breaks a render. Cause. Template-string HTML with no escaping, and esc() declared locally in 25+ places rather than globally. In React this trap disappears — JSX escapes by default. The rule is therefore narrow and absolute: dangerouslySetInnerHTML is forbidden outside a single reviewed, allow-list sanitizer used for one purpose.

11 Migration guidance

The goal is that staff experience the rewrite as continuity, not as a new product to relearn during high season.

Extraction order

1 · Tokens, with no visual change
Publish packages/ui/tokens.css and verify against the monolith’s computed values. Mechanical and independently reviewable.
2 · The status map
Build StatusPill plus the complete status→tone table. Every status in the product is enumerated here; a status not on the list is a bug in the data model. The highest-leverage single artifact in the migration.
3 · DataTable
Most screens are a table plus a filter bar. A correct DataTable makes every subsequent screen small.
4 · Forms, Typeahead first
Typeahead is the highest-risk control — portal positioning, keyboard, async — and everything else follows the pattern it sets.
5 · Layout shell
Topbar, sidebar, page templates, the sticky-offset hook.
6 · Print, as its own project
Print shares no code with the screen layer beyond tokens. Treating it as a phase rather than a footnote is what stops it being skipped.

Screens follow booking first, per the strangler plan.

Must stay pixel-identical

Dense table geometry
Row count per screen is a learned quantity — change it and every “third row down” reflex is wrong.
Status colors and their meanings
Green-is-good is read pre-attentively. Remapping a hue costs weeks.
The pill recipe — tint + 4px dot + label
The most repeated visual in the product.
Figures in DM Mono, right-aligned
Scanning a column is a trained skill.
Print documents, all of them
These leave the building. A guide sheet that looks different is a support call from a pier.
Sidebar group order and labels · the 42px hero KPI figure

May safely improve

Radius normalization to 6/10/14 — most visible improvement per unit of risk
Dropping glass — ship it with the module port, never as a standalone “we removed the pretty thing” release
One green, one amber, one red, one blue — nobody can name the current variants; nobody will miss them
Focus rings everywhere · consistent disabled states · real empty states — currently absent, pure gain
Skin consolidation 17 → 8 — per-module as each is ported, never in one sweep
Dark mode — new capability, opt-in, system default

Verifying parity

  1. Token diff. A script reads the monolith’s computed :root and diffs it against tokens.css. Every intentional difference is listed with a reason — that list is the review artifact.
  2. Status coverage test. Assert every value in every status enum has a tone and a bilingual label. Fails the build on a gap. This alone would have caught audit defect #7.
  3. Side-by-side screenshots at 1440 and 1024, per screen, reviewed by someone who uses the screen.
  4. Print diff. Print each document from both systems to PDF; compare page count, breaks and column positions. A changed page count is a regression even when it looks fine.
  5. The 40-row test. Every list screen reviewed with 40+ rows of real data. Density problems are invisible at 5 rows of fixtures.
  6. Both languages, every screen, with the longest real strings — not lorem.

12 Governance

Adding a token

Rare, and it should feel rare. Is this a new concept, or a value that belongs to a component? Propose with three call sites → confirm nothing existing covers it → add with both theme values (light on bare :root, dark repeated in both dark blocks) → add a swatch to the specimen grid → review. Never add a tint or shade of an existing token to solve one component’s problem — use color-mix() at the call site.

Adding a component

Check the inventory first — the answer is usually a variant. If genuinely new: specify purpose, anatomy, variants, the full state set, a11y and the prop contract before writing it. It ships with all eight states, keyboard operation, both themes, both languages and a specimen. Missing any of those, it is not done.

Adding a skin

The highest bar in this document. Justify why an existing skin cannot serve → provide four tokens for both themes → prove AA contrast for text-on-accent and accent-on-panel in both → register and review. A proposal that needs a fifth token is not a skin; it is a request to change the design system.

Composition

Components compose downward only: primitives (Button, Field, Icon) know nothing about domain; patterns (DataTable, FormGrid, Modal) compose primitives; features compose patterns and may know domain. A primitive importing a domain type is a layering violation and fails review.

Keeping the system from drifting back into per-page CSS

#Mechanism
1No literal colors in feature code. Lint bans hex, rgb() and hsl() outside tokens.css and skins.ts. The single most important rule here — it is what the monolith lacked, and it is why the monolith has seventeen visual languages.
2No literal font sizes, radii or durations outside the token file.
3No numeric literal in a sticky top.
4No component definitions inside render bodies.
5No backdrop-filter; no filter/transform on card or field containers.
6No dangerouslySetInnerHTML outside the one reviewed sanitizer.
7Social: this document’s specimens render from the real tokens. If a token changes and a specimen looks wrong, the doc has caught it. The page is its own regression test.

The twenty hard rules

#RuleDetail
01Every figure in DM MonoTabular-nums, right-aligned. Money, counts, dates, times, hours, pax, serials, IDs. No exceptions on screen.
02Thai font in every stackBoth --font-sans and --font-mono name Noto Sans Thai. One Thai font in the product. Line-height floor 1.55 (print 1.7).
03Three radii: 6 / 10 / 14Controls · containers · floating. Full-round and 50% are shapes, not scale steps.
04Six status tones, one sourceNo page re-declares a status color. Fixes audit defect #2 — the highest-leverage structural fix available.
05Status = tint + 4px dot + labelColor alone never carries meaning. Never a dot-only status.
06Zero ≠ missing0 is normal ink; missing is — in --muted. “0 boats available” is an emergency; “— boats available” means the query did not answer.
07cap ≠ licensePaxNever two bare adjacent numbers. Over cap → approval (soft). Over licence → hard block, disabled control. The bare word “capacity” is banned in copy.
08Dates via localYMD()Never toISOString().slice(0,10). Asia/Bangkok, always. At +07:00 anything before 07:00 lands on yesterday in UTC.
09Currency ฿12,450Prefix, no space, comma groups, zero decimals. Negatives as −฿1,200 in danger, never parentheses.
10Sticky top reads a CSS varNever 52. topbar-float-skin already zeroes --topbar. Stacked bars are measured with ResizeObserver.
11Popovers render in portalsNo backdrop-filter anywhere; no stacking context on a form card. This makes the dropdown trap impossible by construction.
12key is a stable domain idNever an index. Never define a component inside a render body. Never conditionally remount a subtree that owns focus.
13Tables scroll inside .twThe page body never scrolls horizontally. min-width goes on the inner table, overflow-x on the wrapper.
14Icons are inline SVG24×24, stroke 2, currentColor. There is no Tabler webfont — icon-font class names in the monolith render nothing.
15focus-visible is never removedOne ring: 0 0 0 3px var(--accent-soft). Focus moves deliberately after every context change.
16Motion is banned where it costsDense tables, the input path, and KPI figures — a number mid-animation is a number that is wrong, and someone will read it.
17No literals in feature codeColors, font sizes, radii, durations live in tokens.css and skins.ts. Lint it. This is what the monolith lacked.
18A skin sets four tokensaccent · accent-ink · accent-deep · accent-soft. Nothing else. Scoped to one route-root element; portals are handled explicitly.
19Print is a product surfaceA4 landscape default, one owner for the margin, print-color-adjust:exact where color is data, and every printed status carries a label as well as a color.
20Density over decoration13px body, 12px tables, 33px rows. If a screen looks airy, it is off-system — the answer is fewer columns, not more padding.
